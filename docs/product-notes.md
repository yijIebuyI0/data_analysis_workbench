# 产品说明与实习面试讲述

## 一句话定位

DataLab 是一个“人在回路”的数据分析 MVP：把上传、评估、逐步确认清洗、聚合分析和 AI 策略串成可回溯流程，降低非技术用户误改数据或拿旧结果做判断的风险。

更准确的叫法是“AI 辅助数据分析工作台”，而不是全自动 Agent。AI 只负责第三阶段的解释和建议，确定性的清洗与计算由 pandas 完成。

## 目标用户与场景

- 目标用户：需要临时分析表格、但不熟悉 Python/SQL 的运营、市场或产品同学。
- 核心任务：快速了解数据质量，完成常见清洗，得到基础统计，并把结果转成可讨论的业务策略。
- 当前场景：本地、单人、一次性分析；不涉及敏感生产数据库。

## 核心用户故事

1. 作为业务分析者，我希望上传常见表格后立即看到数据问题，以便判断能否继续分析。
2. 作为数据使用者，我希望每个清洗动作先看到影响范围并确认，以免误删或误改。
3. 作为业务负责人，我希望通过下拉框完成常见聚合，不必写代码。
4. 作为策略制定者，我希望 AI 的建议明确引用已确认的统计结果，而不是凭空发挥。
5. 作为文件所有者，我希望始终保留原始文件，并单独下载清洗结果与流程记录。

## 关键产品决策

| 决策 | 原因 | 代价 |
|---|---|---|
| 每步“预览 → 确认” | 数据删除和类型转换不可盲目自动化 | 操作次数更多 |
| 清洗后再开放分析 | 避免统计口径在流程中途变化 | 用户不能跳步 |
| 分析确认后再开放 AI | 保证模型读取的是稳定版本 | 交互路径更严格 |
| pandas 做计算、LLM 做解释 | 计算可复现，减少模型算错数字 | 能力不像“全自动 Agent”那样炫目 |
| 只传汇总给模型 | 降低隐私和上下文成本 | AI 无法做行级诊断 |
| 本地 Streamlit MVP | 快速验证流程和需求 | 暂无多人协作与持久化 |

## 成功指标（若进入真实试用）

- 任务完成率：用户能否从上传走到下载结果。
- 清洗效率：完成同一份表格所需时间，相比 Excel 手工操作的下降比例。
- 预览拦截率：用户因预览而取消或修改规则的次数，验证确认机制是否有价值。
- 结论可用率：用户认为 AI 策略中“有数据依据且可执行”的建议占比。
- 结果一致性：相同数据和规则重复运行时，确定性计算结果是否一致。

## 风险与应对

- 自动类型识别可能误判：只给建议，不自动执行；转换失败策略由用户选择。
- 删除空值行可能损失样本：默认选择固定值填充，删除必须主动选择并确认。
- 大模型可能夸大结论：系统提示词要求区分事实、推断和假设，且只提供结构化统计。
- 数据隐私：前两阶段完全本地；调用 AI 前展示将发送的工具消息，不传完整明细。
- 大文件性能：当前限制 500,000 行，超出后明确拒绝，不承诺生产级性能。

## 演示脚本（约 3 分钟）

1. 上传样例文件，指出系统自动发现的空值、字段类型和疑似口径问题。
2. 选择空值处理，先展示影响 2 行的预览，再确认执行；强调原文件未变化。
3. 对客户城市做去空格或值映射，展示变更前后样例。
4. 确认清洗完成，展示数值统计，并按客户类型对订单金额求和。
5. 确认分析结果，展开 AI 工具消息，说明模型看到的是统计结果而不是原始明细。
6. 输入业务问题，展示策略，并下载清洗数据与审计记录。

## 简历表达（按真实完成情况使用）

项目名称建议写：**DataLab｜AI 辅助数据分析工作台（个人项目）**

- 基于 Streamlit 与 pandas 设计三阶段数据分析流程，支持 CSV/XLSX/JSON 数据质量评估、逐步预览确认清洗及可选聚合分析。
- 设计“人在回路”状态门禁和版本失效机制：清洗变更后自动作废旧分析，结果以新文件名导出并保留清洗审计记录。
- 使用 DeepSeek Chat Completions 工具调用，将已确认的统计摘要作为工具结果传给模型，约束 AI 输出可追溯的业务发现、策略与验证指标。

不要写“搭建企业级数据中台”“实现全自动智能决策”或未经真实用户验证的效率提升数字。

## 面试可能追问

**为什么不直接让 LLM 写 pandas 代码执行？**

首版动作有限且可枚举，用确定性函数更安全、可测试。LLM 放在解释层，既保留 AI 价值，也避免生成代码修改用户数据。

**为什么每一步都要确认？**

空值删除、去重键和类型转换会改变样本或口径。预览把影响行数和样例放在决策前，用户承担最终业务判断。

**为什么用工具消息？**

它把“模型请求数据”和“应用提供可信统计”分开；比在用户 prompt 中拼接一大段表格更结构化，也能限制模型只能调用已定义工具。

**下一版做什么？**

先通过 5–10 位目标用户测试验证路径，再按反馈选择规则模板复用、图表推荐、会话持久化或只读数据库连接，不同时铺开。
